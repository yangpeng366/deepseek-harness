# Agent Note: Web 界面远程入口文档

Status: implemented

[English](2026-08-22-web-ui-remote-ingress-documentation.md) | 中文

## 问题

Web 界面的服务器保持在回环地址，但从手机访问的用户没有可遵循的文档来说明如何把这个绑定与完成身份验证的 HTTPS 入口结合。缺少明确指引时，容易改成监听所有地址，或经由未认证代理暴露服务；两者都会把远程文件访问和命令执行置于不充分的保护之后。远程访问还需要应用内目录选择对话框，因为操作系统原生对话框可能要求与主机桌面交互。

## 决策

用户指南将 Tailscale Serve 和带身份验证的 HTTPS 反向代理记录为支持的远程路径。两者都显式让 `dsh` 绑定 `127.0.0.1`，都要求把浏览器实际使用的主机名传给 `--trusted-host`，并把身份验证留给入口层。Tailscale 路径仅限 tailnet；反向代理示例启用 basic authentication，并转发外部 `Host` 请求头与 `/api` WebSocket 升级。可复用 overlay 禁用自适应目录选择器并选择 Host 与 UI 的浏览器对话框提供方，因此无需主机桌面即可选择工作区。

## 曾考虑的替代方案

**让 Web 界面监听 `0.0.0.0`。** 不采用：直接监听会绕开必需的认证 HTTPS 层，暴露界面及其工作区工具。

**把 Tailscale Funnel 作为公网入口。** 不采用：Funnel 提供可达性而非站点身份验证；公开暴露仍必须由带认证的入口负责。

**要求使用操作系统原生目录选择对话框。** 不采用：手机会话无法可靠操作桌面原生对话框。文档中的 overlay 显式选择浏览器对话框，同时保留既有 Host 文件系统提供方。

## 后果

手机用户获得两条保留回环隔离和认证传输的具体路径。运维人员在使用反向代理前必须配置 HTTPS 与身份验证，并确保任一入口转发 WebSocket。指南把远程暴露指引放在首次选择工作区附近，也就是新用户决定 UI 访问方式的位置。
